# 安全职责：TLS、机密与加密

本系统在工程完成阶段不代为提供机构级基础设施安全；以下职责需要机构/部署方落实并记录，属于试点就绪门禁的一部分（见 `docs/release/engineering-complete.md`）。

## 传输加密（TLS）

- 生产 Compose 只暴露 `proxy`（nginx，TLS 1.2/1.3），Postgres/MinIO/API/worker 不发布端口。
- 证书挂载自 `./certs/fullchain.pem` 与 `./certs/privkey.pem`（只读）；私钥权限 `600`。
- 部署方负责：证书签发/续期、吊销与更换流程、证书过期监控。**工程完成不包含自动续期。**

## 机密（secrets）

- 全部凭据来自挂载的 secret 文件（`./secrets/*`，容器内 `/run/secrets/*`），支持 `*_FILE` 环境变量（如 `ICRM_DATABASE_URL_FILE`）；不会出现在环境变量或日志中。
- 部署方负责：`./secrets` 目录权限（建议 `700`/`600`）、口令轮换流程、离职人员访问回收、secret 的备份保护（随备份一起加密存储）。

## 数据卷加密（at-rest）

- 系统内部不做字段级加密（设计决策，见 ADR）；敏感材料的机密性依赖基础设施层。
- 部署方负责：
  - 操作系统/块设备加密（LUKS 等）覆盖 PostgreSQL 与 MinIO 数据卷；
  - 备份加密（本仓库 `scripts/backup.sh` 使用 AES-256-CBC + PBKDF2 口令文件；见 `docs/ops/backup-restore.md`）；
  - 材料与备份的保留制度（机构制度，未落地前不宣称试点就绪）。

## 运行时防护（代码内已实现）

- 无默认账号/口令；生产模式拒绝演示模板/规则生成正式报告。
- 无运行时模型下载/更新：PaddleOCR 模型在镜像构建时下载并 SHA-256 校验，worker 启动时校验产物（`app.paddle_engine.verify_artifacts`）。
- 云端 DeepSeek 门禁：必须同时设置训练承诺确认与明确留存天数，否则云端路径保持关闭；云调用仅记录脱敏请求/响应。
- 审计日志不可修改/删除；材料正文、提示词正文与模型响应正文不落入日志。

## 机构责任清单（试点就绪门禁）

- [ ] 真实脱敏材料与黄金集的机构授权
- [ ] 机构法务/业务对规则、模板与 LPR 的批准
- [ ] 模型供应商协议（不训练、留存、保密）
- [ ] 基础设施加密与保留制度书面化并执行
- [ ] 生产级恢复演练（非演示环境）
